# ascii-art

Консольная программа на Go, которая превращает текст в ASCII-арт. На вход подаётся строка, на выходе — та же строка, «нарисованная» крупными символами из готового шрифта-баннера.

## Пример

```
$ go run . "Hello"

 _    _          _   _          
| |  | |        | | | |         
| |__| |   ___  | | | |   ___   
|  __  |  / _ \ | | | |  / _ \  
| |  | | |  __/ | | | | | (_) | 
|_|  |_|  \___| |_| |_|  \___/  
                                
                                
```

## Возможности

- Рендеринг любого текста из печатаемых ASCII-символов (коды 32–126).
- Три шрифта на выбор: `standard`, `shadow`, `thinkertoy`.
- Поддержка переноса строк: символ `\n` во входной строке даёт пустую строку в выводе.
- Понятные сообщения об ошибках при отсутствии файла шрифта или недопустимом символе.

## Требования

- Go 1.21 или новее.

## Установка

```
git clone <url-репозитория>
cd ascii-art
```

В корне проекта должны лежать файлы шрифтов: `standard.txt`, `shadow.txt`, `thinkertoy.txt`.

## Использование

```
go run . [STRING] [BANNER]
```

- `STRING` — текст для отрисовки (обязательный аргумент).
- `BANNER` — имя шрифта без расширения (необязательный, по умолчанию `standard`).

### Примеры

```
go run . "something"
go run . "something" standard
go run . "hello" shadow
go run . "hello" thinkertoy
```

Чтобы вывести несколько строк, передайте символ переноса прямо в строке:

```
go run . "hello\nworld"
```

## Как это работает

Каждый файл шрифта описывает глифы для ASCII-символов с кодами от 32 (пробел) до 126 (`~`). Один глиф занимает 8 строк, после каждого глифа идёт пустая строка-разделитель — итого блок из 9 строк.

`banner.LoadFont` читает файл, разбивает его на строки и раскладывает глифы в `map[rune][]string`, где ключ — символ, а значение — его 8 строк. По ходу проверяется, что файл не оборван и содержит все ожидаемые глифы.

`banner.Render` идёт по входному тексту построчно. Для каждой строки он восемь раз проходит по символам — по одному ряду глифа за раз — и склеивает соответствующие фрагменты в общий результат через `strings.Builder`. Пустая входная строка превращается в пустую строку вывода, а встреченный неподдерживаемый символ приводит к ошибке.

## Тесты

```
go test ./...
```

Покрыты основные сценарии: ошибка при отсутствии файла шрифта, ошибка на неподдерживаемом символе, корректная сборка глифов и обработка пустых строк между баннерами.

## О шрифтах

Файлы `standard.txt`, `shadow.txt` и `thinkertoy.txt` — стандартные баннер-шрифты, предусмотренные заданием. Вся логика загрузки шрифтов, рендеринга, разбора аргументов и тесты реализованы в рамках проекта.
